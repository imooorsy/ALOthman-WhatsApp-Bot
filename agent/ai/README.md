# منطق واتساب إيجنت المكتب

تنفيذ مرجعي بـNode.js دون اعتماديات خارجية. يتبع قاعدة معرفة المكتب ([office-knowledge-base.md](../.specify/specs/001-legal-whatsapp-agent/office-knowledge-base.md)): المساعد «عثمان» يفهم رسالة العميل فهمًا منظمًا، ويفرزها ببطاقة تخصصها، ثم يحيلها للفريق أو يعرض استشارة أو خدمة بسعرها المعتمد أو يعتذر عن المستبعد. مضمون كل رد من النصوص المعتمدة في `config/approved-replies.json`، ويصل العميلَ بجمله وكلماته. النموذج لا يكتب نصًا للعميل: يختار فقط عبارات مجاملة من قائمة ثابتة (رد التحية، الدعاء، العزاء بعد ذكر وفاة، التمهيد قبل سؤال)، والكود يضعها حول جمل النص المعتمد (`composeCourtesy` في `ai/src/phrase-check.js`)، ثم يُفحص الناتج قبل الإرسال. إذا لم يمر الفحص، أو تأخر النموذج، يُرسل النص المعتمد كما هو (DESIGN.md القسم 4.5، والمعيار 55 في spec.md). العقد الكامل في [DESIGN.md](DESIGN.md).

## التشغيل والتحقق

من جذر المشروع:

```text
npm test                 الاختبارات كلها
npm run validate:replies فحص ملف الردود
npm run replies:doc      مستند مراجعة الردود للمكتب (replies-draft.md)
npm run samples          محادثات سيناريوهات المكتب كما يرد عليها النظام
npm run review:pack      12 محادثة لقارئ مستقل
npm run grade -- out.json [held-out-out.json]   تقييم مخرجات نموذج على مجموعة الاختبار
npm run report:models    تقرير تاريخي من المخرجات المحفوظة (انظر «حالة التسليم»)
npm run eval:live        التقييم المقاس بمفتاح API، وهو شرط ليرد الخادم على أي عميل
```

لا يلزم `npm install`.

## الاستخدام من الخلفية

```js
const { createState, handle } = require('./ai/src/flow');
const { loadReplies } = require('./ai/src/replies');
const { buildRecord } = require('./ai/src/record');
const profile = require('./config/office-profile.json');
const triage = require('./config/triage.json');

const env = { replies: loadReplies(), profile, triage };
const state = createState();
// flags: مخرجات النموذج بعد التحقق من مخططها. text: نص العميل، به يُتحقق أن الاسم
// والتواريخ والمبالغ كتبها العميل فعلًا. at: ثوانٍ منذ بداية المحادثة.
// outOfHours: هل وصلت الرسالة خارج ساعات العمل.
const out = handle(state, { type: 'text', at: 0, text: clientText, flags, outOfHours }, env);
const record = buildRecord(out.state, triage); // سجل الإحالة للموظف، يبنيه الكود لا النموذج
```

تحفظ الخلفية `out.state`، وتعالج `out.events`، وترسل `out.messages`. هذا كله موصول فعلًا في `server/engine.js`.

## التقييم قبل التشغيل

لا يرد الخادم على أي عميل قبل تشغيل كامل لـ`npm run eval:live` يجتاز كل الحدود (`server/evaluation.js`). التشغيل:

1. **مجموعة الاختبار** (`ai/tests/data/test-set-v2.json`): الرسائل الـ190 الأولى بأرقامها، وبعدها رسائل أُضيفت للحدود: طلب موظف، وسؤال «أنت بوت؟»، وعميل حالي، وغير عميل، ورسائل غير مفهومة، وبيانات حساسة، وأجوبة أسئلة الكتالوج، ومواعيد ومدد تُحسب من يوم التقييم، ومبالغ بأرقامها وحدودها، ومحاولات تطلب تصنيفًا معينًا. يقيّمها `ai/tests/grade.js`، وحدوده: دقة المسار 90%، والتقاط كل مسار حرج (طلب موظف، سؤال الهوية، عميل حالي، غير عميل، غير مفهوم) 95% أو 90%، والسؤال القانوني 98% مع سقف 2% للرسائل غير القانونية التي تُعامل كقانونية، والمواضيع الإدارية، والبيانات الحساسة (تُلتقط ولا تُنسخ)، وأسئلة الكتالوج المجاب عنها، والمبالغ والتواريخ بأرقامها، والأسماء والمدن. المجموعة التي تقل عن 20 رسالة تحتمل خطأً واحدًا.
2. **سيناريوهات المكتب** (`ai/tests/data/office-scenarios.json`): رسالة رسالة بفهم النموذج نفسه، وكل رد يُكتب بالنموذج ويُفحص. الخطأ الحرج (طلب للموظف، الاستعجال، النتيجة، الاعتذار أو العرض وسعره) يُسقط التشغيل؛ والخطأ البسيط (سؤال آخر أو صياغة أخرى مع القرار نفسه) مقبول في 5% من الخطوات على الأكثر.
3. **زمن الرد:** كل خطوة بوقت التجميع ثم وقت الفهم والكتابة أو مدة الكتابة الظاهرة أيهما أطول، ومعها وقت الإرسال (700 ملي ثانية، `--send-ms`). الفهم الذي فشل أو تجاوز مهلته يُحسب بمهلته، وكذلك الكتابة. الرد الأول في 10 ثوانٍ والتالي في 15، لكل منهما في 95% من الردود.
4. **أعطال الخدمة** (429 و529 و5xx وتجاوز المهلة وانقطاع الاتصال) يُعاد طلبها مرتين بعد انتظار، وتُحصى منفصلة عن أخطاء النموذج.
5. `--repeat N`: يجب ألا يقع خطأ حرج في أي تشغيل، والحدود تُحسب على مجموع التشغيلات.

يسجل التشغيل بصمات ما قيس به، ولا يغطي الخادم إلا إذا طابقت ما يستخدمه هو: النموذج وإعدادات طلباته وحدود المخرجات، وإصدار API ومهلتا الفهم والكتابة، والتعليمات والمخطط، والنصوص المعتمدة والقواعد، وكل ملفات `ai/src` و`server/providers.js`، وقوائم خدمات المكتب التي يقرؤها النموذج، ومجموعة الاختبار والسيناريوهات ومصححاتها. أي تعديل في أحدها يستلزم تشغيلًا جديدًا. وتاريخ «اليوم» في التقييم ثابت: الخميس 12 نوفمبر 2026، وأمثلة التعليمات تحسب من يوم آخر حتى لا تُنسخ أرقامها.

### المجموعة المحجوزة: من رسائل المكتب الحقيقية

رسائل مجموعة الاختبار كلها رآها من يضبط التعليمات، فلا تقيس وحدها ما لم يُضبط عليه. المجموعة المحجوزة ملف خارج المستودع لا يراه من يعدّل `ai/prompts/understand.md`:

1. **الجمع:** يأخذ شخص من المكتب لا يعدّل التعليمات رسائل عملاء حقيقية، من محادثات المكتب السابقة أو من أسابيع التجربة الأولى: الرسالة الأولى في المحادثة، والأجوبة القصيرة مع سؤال المساعد الذي سبقها. يستبدل الأسماء وأرقام الجوال والهويات والحسابات بأخرى وهمية بالشكل نفسه، ويترك بقية الكلام كما كتبه العميل.
2. **التغطية:** نحو مئة رسالة أو أكثر، فيها ما يكفي من كل مسار حرج (طلب موظف، «أنت بوت؟»، عميل حالي، غير عميل، سؤال قانوني، سؤال إداري، مبالغ ومواعيد)، بالعربية والإنجليزية كما تصل.
3. **التوقعات:** لكل رسالة توقعاتها بصيغة `ai/tests/data/test-set-v2.json` (`id` و`message` و`last_bot_message` و`expect`؛ الحقول موثقة في رأس `ai/tests/grade.js`). يكتبها من يعرف قواعد المكتب، ويراجعها ثانٍ. المدة إلى موعد أو منذ انتهاء العمل تُحسب من الخميس 12 نوفمبر 2026، أو تُترك.
4. **الحفظ:** ملف JSON خارج مجلد المشروع، بصلاحيات بيانات العملاء نفسها، لا يُرفع إلى المستودع ولا يُرسل لمن يضبط التعليمات. يُرفض الملف إذا كان داخل المستودع.
5. **التشغيل:** `HELD_OUT_SET=/المسار/held-out.json` في `.env.local` قبل `npm run eval:live`، أو في سطر الأمر مع `npm run grade -- out.json held-out-out.json`. تُرسل رسائله للنموذج مع كل تشغيل، وتُطبق عليها الحدود نفسها، ويسقط التشغيل إذا لم يحققها. لا يُطبع ولا يُحفظ منها إلا الأعداد: لا رسالة ولا مخرج ولا رقم رسالة فشلت. ويسجل التشغيل عدد رسائلها وبصمتها.
6. **التجديد:** الرسالة التي اطلع عليها من يضبط التعليمات لم تعد محجوزة: تُنقل إلى مجموعة الاختبار، وتُستبدل برسالة حقيقية جديدة.
