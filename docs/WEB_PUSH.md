# Firebase Web Push

Background push uses the Firebase web SDK and Firebase Admin, alongside live Socket.IO alerts. Public Firebase configuration and NEXT_PUBLIC_FIREBASE_VAPID_KEY belong in apps/web/.env.local. GOOGLE_APPLICATION_CREDENTIALS belongs only in apps/api/.env and points to a private service-account JSON. Never commit that file or put it in NEXT_PUBLIC variables. On Render mount it as a secret file at /etc/secrets/firebase-service-account.json. Run migrations and restart/build the relevant services after configuration changes.

Sign in, enable desktop notifications, click **تفعيل الإشعارات** and allow browser permission. The green **إشعارات الخلفية جاهزة** status confirms enrollment. The root-scope service worker is /firebase-messaging-sw.js. Registrations belong to the authenticated staff member; logout removes them. Delivery checks the active staff session to avoid notifications after logout/account changes. The worker does not cache legal transcripts or authenticated API responses.

Unread eligible notifications create durable pg-boss deliveries. Payloads contain opaque identifiers and generic Arabic text, without client names, phones or case summaries. Desktop preferences, read state and age are checked before sending. Invalid registrations are removed. Delivery IDs suppress repeated delivery of the same push; explicitly requested tests have distinct IDs/tags. Foreground push and socket notifications share deduplication. Urgent sound reminders still require an open tab.

The API must stay running, browser permission must remain allowed, and the OS/browser must permit background delivery. Closing a dashboard tab is supported; fully exiting the browser or disabling its background services can prevent immediate banners. The worker requires a valid staff session. Firebase acceptance does not establish that the OS displayed every popup.

For an intentional five-notification test, close the dashboard tab while leaving the browser running, then run `node scripts/send-push-test.mjs` from the repo root. It reads local seed credentials from the API environment, chooses that admin's latest registered browser, schedules five notifications two seconds apart, and prints delivery states. POST /push/test also supports an owned registrationId, count 1–5, intervalSeconds 2–30 and delaySeconds 0–120. GET /push/test/{batchId} reports states. Do not run the test automatically or repeatedly without an intended test request.

Local verification: Firebase accepted all five notifications in the requested closed-tab batch without errors. OS banner count remains unconfirmed. Automated tests cover scheduling, preference/read checks, generic payloads, sanitized retries, five distinct worker notifications, duplicate suppression, expiry and wrong/logged-out sessions.
